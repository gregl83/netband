# Scheduling, health, cooldowns, and fairness

Netband maintains one persisted schedule per canonical provider ID. The cap is global
to the provider, not per process, command, or interface. A reservation is recorded
before the first NDT7 network connection, so crashes and restarts cannot restore it.

## Planned opportunities

For a UTC day, the scheduler divides the remaining interval into `daily_max` equal
strata. It selects one point from the centered `slot_jitter_pct` portion of each
stratum using OS-seeded persisted randomness. At the default 50 percent, each point is
in the middle half of its stratum. It then enforces minimum spacing and discards missed
slots instead of creating a catch-up burst.

This deterministic documentation fixture starts at `2026-08-30T00:00:00Z`, uses the
M-Lab defaults and RNG seed 7, and produces:

| Opportunity | UTC slot |
| --- | --- |
| 1 | `2026-08-30T02:54:48.327Z` |
| 2 | `2026-08-30T10:24:11.652Z` |
| 3 | `2026-08-30T15:32:43.743Z` |
| 4 | `2026-08-30T21:16:35.107Z` |

The documentation contract test executes that same clock/seed. Real schedules differ
because their random seed is generated by the operating system and persisted.

## Ping health trigger

The health window retains six ping rounds by default and requires at least six total
probe samples. Degradation begins when either:

- packet loss is greater than or equal to 50 percent; or
- configured p95 RTT is greater than or equal to `rtt_threshold_ms`.

One degradation episode can request one early bandwidth opportunity. It does not add
capacity: the trigger consumes one existing remaining allowance, honors minimum
spacing/cooldown, and replans the unused opportunities across the remaining UTC day.
The trigger stays latched until three consecutive recovery rounds have loss strictly
below 10 percent and, when enabled, p95 RTT strictly below its threshold. A pending
trigger expires after 30 minutes by default and requires a successful ping in its
originating interface before NDT7 admission.

Ping rounds continue while an admitted NDT7 test runs. Those rows carry the bandwidth
run ID and the `setup`, `download`, or `upload` phase captured when the round starts.
They are recorded for loaded-latency analysis but do not enter the trigger or recovery
health window, preventing Netband's own test traffic from creating another trigger.

At the fixed fixture clock, a qualifying loss decision at `01:00Z` becomes one
`ping_loss` opportunity, a successful reservation leaves three allowances, and the
remaining three slots are recalculated between the spacing boundary and midnight.
Four reservations suppress any fifth manual, scheduled, or triggered start.

## Rate limits

Provider-wide limits are retained in scheduler state. A valid `Retry-After` value is
used exactly, bounded by the end of the UTC day. Without one, backoff starts at 60
seconds, doubles through the configured 16-minute ceiling, and adds persisted random
jitter. Locate `204`, `429`, and relevant `503` responses and direct WebSocket `503`
responses are classified according to provider scope. Deferred discovery is attempted
at most five times; a run already reserved is never refunded.

Changing a direct provider's cap or spacing replans its remaining day without deleting
runs already used. Changing its canonical endpoint creates a distinct hashed provider
identity. Tokens/query values do not affect that identity.

## Multiple interfaces

Ping rounds are serialized across explicitly selected interfaces and rotate in order;
targets inside one round run concurrently. Planned NDT7 opportunities use deficit
round-robin selection so healthy interfaces differ by at most one opportunity when the
global budget permits. A triggered opportunity remains attributed to its originating
interface and counts against that interface's fairness deficit and the same provider
allowance. An unavailable interface is skipped with bounded recovery backoff and cannot
block another interface. Netband records only interface/source bindings actually used.
While NDT7 is active, ping rounds temporarily stay on its selected interface so each
loaded sample has direct interface attribution. Normal rotation resumes afterward.

Scheduler state, its initialization marker, backup, reservation ledger, and lock are
operational data. See [Service operation](service.md#state-recovery) before recovery.
